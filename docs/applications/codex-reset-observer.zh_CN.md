# Codex 重置观察器 v2.4

面向 240 × 320 AI Passport 的独立只读公告工具，数据来自
[Codex Resets](https://codex-resets.com)。它不是 OpenAI 官方软件，也不是个人额度表。
界面参考原站的奶油纸底、墨色描边、黄色时间贴和粉蓝统计卡。

## 四页与按键

上下键切换“概览、近期历史、统计、设置”。概览短按确认进入大屏时间所对应事件的原文，
正文中上下翻页（含最后来源页）、短按确认返回概览；没有事件时不进入空白正文。
统计页短按确认刷新。
设置页按确认进入选项，上下选择、确认修改或进入；末项“返回首页”用于返回。
确认键在 500 ms 内松开，仅执行普通短按，完全不弹出休眠界面。达到长按阈值后才
出现暖色月亮弹窗，圆环从空开始，在剩余 1.5 秒内填满；总按住时长仍为 2 秒。
不显示百分比或秒数。弹窗出现后、未满时松手，圆环用 250 ms 平滑退到空再关闭，
该次手势绝不作为单击。退场和松键保护期间的新按键全部吞掉，稳定松键后才接收
新手势，防止快速重新点击造成残留操作。满环后提示“松手，晚安”，无需二次确认；
仍需全部按键稳定松开 250 ms，并经过原有 HTTP、无线和外设安全关闭流程才入睡。
进度按单调时间戳计算，持久 LVGL arc 约每秒更新 25 次，不逐帧重建页面。
其他按键、焦点变化或输入队列溢出会取消；蓝牙配网时阻止休眠，HTTP 忙时必须
先按原有超时边界结束请求。子页短按保存/返回，清除网络页短按确认清除、上下取消。
独立电源键保留硬件开关用途，不当导航或休眠键，因为 BSP 尚无已确认的短按事件。

概览始终把未来区放在最近一次重置上方，两块同时可见。
有 scheduled 时，上方大卡显示真实本地计划时间；未给时间则显示尚未公布，
时间已过仍显示等待确认，下方小卡保留最近一次简行。没有计划时，上方未来卡
缩小，下方大卡显示最近一次已执行事件的“1天9小时前”等中文相对时间。
主次由是否存在明确计划决定，不比较公告新旧；确认进入当前大卡对应原文。
未来卡无论大小均为浅蓝，最近一次卡无论大小均为白底与黄色时间强调，
颜色跟随事件语义，不随主次大小互换。
常规重置和备用额度发放分别标明。
概览不显示公告正文。有效 watch 只作次级“预测”提示，绝不冒充确定计划，
也不替换历史主事件。

历史平均间隔保留在统计页，为双事件卡留出清晰空间；它是历史参考，
不当作固定重置周期，更不据此计算下一次时间。
缺失保持未知，统计页保留总次数、平均间隔和距上次，不编造最长等待。
最近事件时间依站点公告/观察记录，不伪称精确执行时刻。

只有概览实际渲染成功才记录可读事件。应用在 RTC 内存中只保留一份当前状态缓存，
界面模型和阅读选择引用其中的原文。阅读时固定已展示的版本及日期、类型、来源和时区；
状态请求等返回后再执行，已在途的响应会校验但不能替换固定正文或其 ETag。
返回时按照原有防抖和退避重试被延后的响应。如果进入前已展示版本发生变化，先刷新概览；
显示锁获取失败也不会选中尚未展示的新数据。

每条公告接收上限 1120 字节，为 280 个 Unicode 码点各预留最多四个 UTF-8 字节，
保留合法 UTF-8 并在完整码点边界截断；预测窗口仍为 96 字节。
[X 按加权字符计数](https://docs.x.com/fundamentals/counting-characters)，组合 emoji 和链接
有特殊规则。设备采用字节预算，不作为 X 发帖长度校验器：超过 1120 字节的特别长的
组合序列或展开链接仍会明确标注为节选，Premium 长文不在此预算内。

正文按实际字体像素宽换行，每页七行，长单词和 URL 也可断行。仅保存引用当前原文的
页面边界，按需生成正在显示的页，不缓存整套分页或正文副本。在字节预算内，最多
160 个正文页也足以覆盖全为换行的输入（280 个换行码点需要 40 页），普通文字页数远少于此。
保留简洁日期、小页码与低调来源名 Codex Resets；仅实际超限或缺字替代时提示。
不静默丢字、不加载完整 CJK 巨型字体。原文以 API 提供语言显示，不远程翻译，
不硬编码当前公告。正文之后独立增加最后一页真实二维码，不挤占正文面积。
二维码编码所选事件 API 提供的完整 HTTPS source.url，限 120 字节与 X/Twitter/Codex Resets
白名单域名；观察记录、缺失、不安全或过长链接回退至 `https://codex-resets.com/zh-CN`，
明确标“查看数据来源”，不冒充原文。使用项目已有 LVGL 编码器、中级纠错，192px 画布内
整数模块至少三像素，四周白色静区至少四模块。分配失败显示暂不可用。
上下键在正文与来源页之间循环，确认返回首页；RTC 缓存升为 v6，保留扩展原文和已验证的历史窗口并拒绝旧布局。

## 内存预算

每个原文缓冲区含 NUL 为 1121 字节。默认八周配置的 RTC 状态为 3016 字节，包含
当前状态及睡眠/历史策略；界面和阅读视图不保留正文副本。相对原有副本与八页矩阵，
计入缓存互斥量后，相关常驻存储合计估算减少约 2.7 KiB。LVGL 内存池仍为 24 KiB，
主机渲染峰值为 18288 字节，页面压力测试没有出现分配增长。

ESP32-C3 编译器记录的单函数栈帧为：主函数 656 字节、正文布局 1440 字节、
当前页格式化 1168 字节、状态解析 2912 字节。这些不是整个调用链的用量，也不是
实机高水位。主任务/数据任务栈仍为 3584/8192 字节；运行时栈、空闲堆及 TLS 活动
时的最大空闲块仍需实机测量。

## 近期历史

以周一为首行，显示包含本周的近期 UTC 日历，先采用八周窗口。
`RESET_HISTORY_WEEKS` 统一控制查询、缓存和绘制，可在构建时改为六周，
不增加设备设置，也不抓取全部历史。八周布局采用14像素格子，横向7像素、纵向6像素
间隔，保持12像素标签并为图例留白。图表明确按 UTC 分日，不受其他页面本地时差影响。

常规与备用分别标色，同一天两种事件都能保留。未来日期、未知日期和已确认无事件
使用不同状态；只有完整且校验通过的分页周期，才能把查询截止时刻之前的空日标为
未重置。失败、分页未完或达到上限不能冒充空日；保留的完整缓存会明确标过期，
没有覆盖到的日期保持未知。格子表示事件种类，不编造每天次数。

进入历史页或按确认时按需请求，复用原 HTTP 任务、TLS 校验、暂停确认和退避。
每轮最多四页、每页25条、响应16 KiB、整轮30秒；先释放 TLS 再解析 JSON，
不并发启动第二个 TLS 连接。完整缓存最多复用六小时，但 UTC 跨日/跨周或
已知有更新重置时提前失效；深睡恢复的历史也需重新核验。自动熄屏和深睡
继续沿用原有安全停止流程。

## 设置与省电

- Wi-Fi 开关会保存。关闭保留凭据，但停止扫描、蓝牙配网、重试与自动重连；
  开启后连接已保存网络。
- 自动同步可选 5/15/30/60 分钟，默认 15 分钟。手动和唤醒刷新可绕过自动周期，
  但有 30 秒防抖，且必须遵守失败退避及服务端 Retry-After，界面显示剩余等待。
  五分钟不是官方公布的硬性限频。
- 本地时间使用明确的固定 UTC 偏移，每步 15 分钟，范围 UTC−12 至 UTC+14。
  默认 UTC，不猜测位置，不自动切换夏令时。
- 亮度 20/45/75%。普通查看状态 30 秒调暗；自动熄屏可选 5/10/30 分钟或关闭，
  默认 5 分钟。时间从最后一次按键累计，而非在调暗后额外加上设置时长。
  关闭自动熄屏会同时关闭自动深睡，但保留 30 秒调暗。
- 到设置时间先关背光，再固定等待 15 秒反悔期；此时网络与外设继续工作。
  反悔期结束后才开始安全关闭。首次按键只亮屏并消耗整个手势，不导航、不修改
  设置，也不弹出手动休眠动画。
- 自动关闭全程不打开睡眠页、不重新点亮。可逆失败恢复服务但保持黑屏，五分钟
  冷却后重新给出 15 秒反悔期再尝试。不可逆失败安全重启，以一次性标记保持黑屏；
  首次按键恢复显示。标记只对受控软件重启有效，不影响物理开机或深睡唤醒。
  手动休眠仍显示原有进度及错误提示。
- 只有真实用户按键重置空闲计时，API 轮询不算活动；配网、按住键、手势、设置编辑、
  取消及关闭准备暂停计时。配网和清除网络仍是不同操作。
- 保留原有 NVS 键 `sleep_minutes` 和 5/10/30/关闭档位。升级后，已保存的分钟数
  解释为熄屏时间，之后再给 15 秒反悔期；不重置偏好或 Wi-Fi 凭据。缺少该键时
  默认五分钟，不丢失原有 Wi-Fi OFF 设置。
- 手动按满圆环并松开仍可休眠，两条入口复用同一安全关闭流程，不再二次确认。
  睡眠时不联网、不定时唤醒、不后台更新。
  以底部确认键为主要唤醒入口，**仍需实机验证**；入睡前松开所有键。若无法唤醒，使用硬件
  电源控制恢复。三个功能键共用 GPIO0，上下键也可能唤醒；软件不能区分哪一个电阻梯按键造成 LOW 唤醒。

入睡前必须等 HTTP 完成清理和无线关闭确认。按键在稳定松开后从 ADC 转为数字
GPIO，再按板级顺序关闭电量计、codec、总线和屏幕；不可逆关闭之后的失败会安全
重启。取消休眠恢复服务并等待按键松开。带校验的 RTC 缓存可跨深睡保存，断电不保证。
唤醒先显示旧数据；只有 Wi-Fi 开启才连接，完成本次 SNTP 校时后更新，并保留退避。
不会定时唤醒或立即反复入睡；若自动模式开启，新一轮长时间闲置可再次触发。
不声称未经测量的续航或休眠电流。

## 配网与安全边界

开启 Wi-Fi 后，进入配网页按上键，手机微信打开完整名称为
**蓝牙配网-FoloToy AI PASSPORT** 的小程序，选择 `BLUFI_FoloPassport`，
提供 2.4 GHz 网络信息。窗口仅显式按键开启，180 秒、成功或取消后关闭。
密码不嵌入固件、不写日志；获得 IP 后才保存到应用专用普通 NVS 记录，
保存与连接状态分别报告。候选连接失败不会覆盖原网络。存储不额外加密，
安全边界与原有设备 NVS 相同。

传统 BLUFI 不认证对端，完成 DH 协商后也不强制每个接收帧加密。附近参与者在配网
窗口内可能替换为可连接的新网络，因此仅在可信近场环境操作。本应用保留官方参考
提交 `9c039cc5127f22072afa83bedb7fa3d8efe635ad` 的协议，没有私有入口挂钩或自制加密。

HTTPS 使用 CA 证书包与主机名校验，不跟随重定向，有响应/JSON/超时边界、ETag
缓存及退避。网络需要 DNS/NTP/HTTPS，不支持网页认证热点。更新失败保留缓存。
公告原文有接收、分页和字形边界；界面不展示 SSID 或密码。

## 构建与验证

激活 ESP-IDF 5.5.3 后，在项目目录显式运行：

```bash
python3 tools/apply_blufi_safety_patch.py --apply
./tools/validate.sh
```

脚本验证 SDK 版本和精确源码哈希，拒绝未知修改，重复应用安全。补丁和清单位于
`tools/patches/`，仅修正短分片及 1025 字节重组边界，满足本应用最大 DH 消息，
不改变加密语义，不作为通用上游修复。共享 SDK 的其他工程也受此本地补丁影响，
若需原始基线请另用干净 SDK。固件门禁验证补丁并使用全新配置，按外部上拉的按键
电阻梯要求关闭内部睡眠 GPIO 电阻。

主机测试覆盖解析、HTTP/RTC/退避、导航/设置/时间转换、Wi-Fi OFF/延迟事件、
按键 ADC 交接、休眠顺序和 SDK 分片边界。
[真实 LVGL 预览](../../tools/reset_ui_preview/README.zh_CN.md)使用相同的 12/16 px
中文字形及小型 24 px 相对时间子集与 BSP 半径 30 的圆角裁切，并检查反复换页内存；不等于实机照片或验收。

待实机验证：屏幕/字形、按键与确认键唤醒/无立即唤醒、小程序兼容性、Wi-Fi/TLS、
NVS 保存、取消恢复、运行内存及整板电流。合并镜像从 0x0 刷写，可能重置设置，
需另行批准。已通过验证的早期版本已留档，本次构建不会自动更新或刷写设备。

## 确认键唤醒的电气依据

板级定义为 10 kΩ 外部上拉、确认键 2.2 kΩ 下拉，3.3 V 时约 595 mV。
ESP32-C3 输入 LOW 最大保证电压是 0.25 × VDD，即 3.3 V 时 825 mV，
名义数值支持确认键拉低唤醒；上下键名义电压也在 LOW 范围内。
这不是实机唤醒测试，正常 ADC 识别窗口也比数字 LOW 保证范围更宽。
见[官方 ESP32-C3 数据手册直流特性](https://documentation.espressif.com/ESP32-C3_Datasheet_en.pdf)。
保留原有稳定松键、释放 ADC、数字 GPIO 高电平检查后再配置 LOW 唤醒的流程。
醒后输入须连续松开 250 ms 才放行，长于 180 ms 单击延迟，唤醒按键不会触发刷新
或立即再次进入休眠提示。

## 配网兼容性诊断

请以[官方 Wi-Fi 配网说明](../development/engineering/wifi-provisioning.zh_CN.md)为准，
确认自己打开的是配网入口，并记录提示出现的阶段；当前证据不足以断定“使用了其他
固件”提示的具体根因。EspBlufi 是官方参考代码提及的标准公开兼容客户端，可由用户
自行选择；本次开发没有安装新客户端、改广播名冒充出厂固件或绕过识别校验。
v2.3 恢复了官方示例的 BLUFI 协议错误回报路径，仅记录数字错误码，且只在有效配网
连接期间回发。它是独立诊断改进，不代表已修复上述中文提示，也不会记录密码或 SSID。

## 重启后网络恢复修正

在固定 ESP-IDF 5.5.3 的 ESP32-C3 Wi-Fi 库中，相同 RAM 配置可能使
`esp_wifi_set_config` 直接返回成功，跳过 NVS 写入；切换 FLASH 存储模式本身
不会把已验证的 RAM 配置刷入 NVS。静态库调用链支持这个失效机制，
但不能代替用户设备的日志或重启实测。

本版改用应用专用、带版本/长度/完整性检查的有界 NVS 记录，候选取得 IP 后才
提交并读取验证。驱动保持 RAM 模式；首次没有应用记录时兼容读取原驱动存档。
明确清除写入空记录，防止旧驱动存档再次被本应用加载。
这不是安全擦除：旧驱动记录及旧闪存页可能仍在，降级旧固件可能读到旧网络。本 SDK 在 set_blob 时即可写入；commit/读回失败不承诺持久值回滚。
保留旧网络的内存副本，存储未核验时明确报错，不假报保存成功。保存失败独立显示，不把
当前联网等同于重启可恢复；初始化失败后允许用户关闭再开启重试。
配网页显示无凭据、连接中、失败数字码等状态，不展示 SSID、密码或密钥。

如果旧固件重启前从未真正保存网络，本更新无法找回已丢失的密码。升级后可能需要
重新配网一次，再实测普通重启与深睡唤醒是否恢复连接。
