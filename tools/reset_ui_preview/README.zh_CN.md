# 真实 LVGL 重置界面预览

这是固件展示层的主机渲染与检查工具。它直接编译 `main/reset_ui.c`、
`main/reset_presenter.c`、有界解析器 `main/reset_feed.c` 以及固件相同的中文字体，
使用固定版本的 LVGL 9.5 托管源码、240 × 320 RGB565 显示、40 行局部绘制缓冲区
以及相同的 24 KiB LVGL 内存池。刷新回调直接调用 BSP 的纯圆角行几何函数，
从 `bsp_display.h` 读取半径 30，并与 BSP 一样将圆角之外填充为黑色。
不会创建网页或 HTML 仿制界面，不访问 USB、
请求网络或烧录设备。

## 运行

需要 C/C++ 编译器、CMake、带 Pillow 的 Python 3 和已解析的
`managed_components/lvgl__lvgl` 源码。在仓库根目录执行：

```bash
python3 tools/render_reset_preview.py
python3 tools/render_reset_preview.py --feed /path/to/captured-status.json
```

第二个命令为可选项，读取本地已有的 `https://codex-resets.com/api/v1/status`
响应，不会下载或上传内容。使用前由固件解析器校验。可通过 `--output` 和
`--build-dir` 指定不同的生成目录。工具不修改固件源码和 LVGL 托管文件。
若 `PATH` 中找不到 CMake，请先激活主机或 ESP-IDF 环境。

## 图片能验证什么

- 按需生成的 `00-captured-feed.png` 使用真实捕获的数据，以响应中的
  `generated_at` 作为参考时钟，电量显示不可用占位值。它不是设备照片，也不是
  即时查询；捕获时间和 SHA-256 见来源记录。
- `01` 到 `17` 是确定性的模拟数据：已更新主页、公告详情、蓝牙配网、危险操作
  确认、离线缓存、首次离线启动、过时的计划、AI 预测、网络错误、储备额度与
  站点观察详情、待执行的储备额度，以及首次请求受限。拼图明确标记了模拟状态，各屏保持原始 240 × 320 分辨率。
- 检查各标签实际字体是否缺字、单行是否裁剪、是否超出屏幕。全部固定文本清单
  字符都会针对生成的 LVGL 字体进行验证，已知缺失的 U+9F98 必须被拒绝。
- 重复更新和 500 次换页在 24 KiB LVGL 内存池中运行真实展示代码。检查记录
  峰值占用、剩余空间、最大空闲块和碎片率。主机指针大小和绘制行为可能与
  ESP32-C3 不同，此结果不能代表设备的总可用堆。

默认输出到 `build/reset-ui-preview/screens/`，包含各屏 PNG/PPM、
`synthetic-states-contact-sheet.png`、`audit.txt` 和 `manifest.json`。
来源清单包含展示层/字体源码哈希、响应哈希和检查结果。即使已保存图片，
缺字或布局失败仍会返回非零退出码。修改界面后应重新查看图片。复用输出目录时
保留已有文件；改变场景集合时请指定新的 `--output` 目录。

设备屏幕、亮度、电量 ADC、按键、真实蓝牙/Wi-Fi、HTTPS/TLS 内存压力、凭据
和实际中文字形仍需单独进行硬件测试。主机渲染不等于 `Device tests: PASS`。

## 字体来源和重新生成

参见[字体资源记录](../../assets/README.zh_CN.md#codex-重置观察应用字体子集)，
了解 Noto CJK 来源、版本、哈希、OFL 许可证、固定文本清单和固定版本转换命令。
`tools/generate_reset_font.py --check` 仅需 Python 标准库，检查源码文本与清单
是否一致，以及生成 C 文件的 cmap 覆盖和字形描述符边界。独立运行的真实 LVGL
检查还会验证各控件实际绑定的字体。
固件运行时不需要 Python、Pillow、主机 CMake 工具、源 OTF 或字体转换器。

## v2.2 长按休眠预览

`hold-to-sleep-actual-lvgl.gif` 每隔 40 ms（25 fps）记录一次固件真实的
`lv_arc`：2000 ms 内从 0% 到 100%，随后显示“松手，晚安”、250 ms 稳定松键
等待状态，以及既有的网络收尾页。模拟在 2600 ms 松键，最后一帧等待状态位于
2840 ms，首帧收尾状态位于 2880 ms。这只是 25 fps 的采样，不会把固件的
250 ms 阈值改成 280 ms。GIF 可能将相同静帧合并为一帧并延长时长。
动图仅保留干净的 240 × 320 LCD 画面，不含百分比、数字计时或工程字幕；
主机渲染来源记录在 `manifest.json`。`hold-to-sleep-progress-strip.png` 展示
四个填充阶段，不加数字标注。标题为“准备休息”，未满提示“松手就返回”，
满环提示“松手，晚安”。中心月牙由两个轻量几何圆形绘制，不分配图片资源
或额外月亮控件。其他 PNG 覆盖松开取消、稳定松键等待，以及
配网阻止休眠。已移除原有独立的第二次休眠确认页。

每次按住手势只创建一次弹窗控件。进度更新保留同一个圆环、标签及底页对象。
弹窗可见时暂时隐藏底页绘制，使用简洁的奶油/深色背景；关闭时仅删除弹窗对象，
恢复底页。只读共享文字样式、静态生命周期文字缓冲区、绘制事件实现的卡片阴影，
使原有 24 KiB LVGL 池足够使用，无需缓存全屏图片。

检查器先预热圆环角度和绘制临时缓冲，再进行 500 次进度更新，验证对象身份/数量
不变、对象删除为零、分配块数和空闲字节完全不变，以及分配器有效性；另保留
500 次换页检查。v2.2 模拟场景的长按检查为 24 个对象、234 个分配块、检查
前后空闲均为 3536 字节，全部检查期间记录的峰值为 18712 字节。
1454 个渲染标签检查全部通过，缺字和裁切均为零。这些是主机内存池结果，
不能替代设备堆或真实按键验收。
