# 真实 LVGL 重置应用预览

工具编译真实固件 UI、展示模型、有界正文布局、数据/历史解析器、UTC 历史助手及
生产长按状态机。使用固定 LVGL 9.5、240 × 320 RGB565、40 行局部缓冲区和保持
不变的 24 KiB LVGL 内存池。刷新回调使用真实 BSP 半径 30 圆角行裁剪函数。
工具不进行网络请求、上传或设备刷机。

## 运行与来源记录

需要 C/C++、CMake、带 Pillow 的 Python 和已解析的托管 LVGL 源码：

```bash
python3 tools/render_reset_preview.py
python3 tools/render_reset_preview.py --feed /path/to/captured-status.json
python3 tools/render_reset_preview.py --history-feed /path/to/captured-history.json
python3 tools/render_reset_preview.py --history-weeks 6 \
  --build-dir build/reset-ui-preview-six --output build/six-week-preview
```

可选捕获文件必须已在本地，由真实固件解析器验证。历史输入必须包含一个完整
捕获分页周期，不接受未完成分页。响应 `meta.generated_at` 为预览参照时钟，
捕获数据屏幕的电量不可用。`00-captured-*` 使用这些捕获数据，其他屏幕均为模拟
输入。工具记录源码/捕获文件哈希、时间和实际编译周数，不是实时查询或设备实拍。
场景变化时使用新 `--output` 目录；旧输出不会自动删除。

## 四页及固定的阅读对象

四个顶层页面为概览、UTC 重置历史、统计、设置，不再有重复的最近重置概览页。

- 首页未来卡始终在历史卡上方。有计划记录时，未来卡放大，不比较两条公告的新旧；
  最近一次变为下面的简短卡。没有计划时，上方小卡显示时间未公布（或明确标注的
  预测），下面最近一次已执行记录成为大卡。颜色始终对应事件：未来卡大小变化都
  保持蓝色；最近一次始终白底、时间使用黄色强调，缩小后也保留黄色时间条。
  大小交换时不会交换颜色。未来大卡增加浅蓝色时间内板和蓝色边线，标题/时间/
  日期/时区层级与最近一次大卡一致，不借用黄色强调。
- 计划时间来自真实 `scheduled_for`，按已设固定 UTC 偏移显示。空时间仍未公布；
  已过计划时间只标等待确认，不能仅凭时钟走过就变成已执行。
- 最近一次使用中文相对时间、精确本地日期和常规/备用类型。时间来自站点的公告/
  观察记录，不宣称是精确执行时刻。
- 预测不替代计划或历史主记录。仅未过期且时钟已确认的预测可在未来小卡显示，并
  明确标“预测”，可附概率。窗口文本被省略或遇缺字时有可见提示，不从原文伪造
  时间戳。历史平均间隔仅放统计，标注“历史”，不是固定重置周期或未来预测。
- 首页短按确认只在存在记录时打开大卡对应原文。应用从最后一次成功显示的首页
  捕获有界快照，冻结正文、类型、日期、时区、截断标记和来源。API 或时区更新
  不会偷换正在阅读的对象；缺少有效快照时不回退读取另一条实时记录。
- 正文上下翻页、短按确认回首页。16px 字体，每页七行、最多八页；在 178px 内
  使用真实 LVGL 字形宽度/字偶距换行，优先空白，长词/URL 按完整 UTF-8 码点拆分。
  输入最多 256 字节，安全规范化 CR/LF/TAB。缺字替换为 `?`，字节/页数超限明确
  提示。正常正文周围仅有低调日期、页码和来源名；不翻译、不执行富文本、不分配
  正文堆缓冲区。
- 最多第九页显示所选来源的精确二维码，或明确标注的数据站点回退地址。192px
  白色底板保留四模块静区，整像素模块不少于 3px。URL 有界并验证，不截断，且
  始终使用阅读快照的来源。

七行设置、自动熄屏/宽限流程和暖色月亮长按动画不因展示/阅读改动而变化。

## 历史日历

同一个 `RESET_HISTORY_WEEKS` 编译常量同时控制查询、缓存、展示模型和 UI。
默认八周，也支持六周，不增加设备设置。列为 UTC 周一开始的周，行为周一到周日；
月份和日期范围采用 UTC，不受公告页本地偏移影响。

- 常规：橙色 `#FF5C29`；备用：浅桃色 `#FFAD7C`
- 同一天两种类型：双色同格，不编造次数
- 已验证无重置：暖灰；未知：白色描边；未来：浅色
- 只有完整验证的全部 API 分页才将覆盖范围标为已知；等待、失败、未覆盖日期
  绝不能画成“无重置”灰格
- 保留并重新投影已有缓存交集；新窗口未覆盖日保持未知
- 等待联网/校时、正在读取、旧缓存和更新失败有不同状态

一个自绘对象绘制浅边框、全部 56（或 42）格和图例色块。单元格为 14px，横向
步长 21px、纵向 20px，分别留 7px/6px 清楚间隔。实色日期去掉厚重黑描边，未知
日期仍保留可区分的描边。星期标签、格子、月份作为一个整体左移 3px：默认八周的实际可视边界为 x=26..210，
框内左右留白 7px/8px；六周也按整个组合居中。月份钳制在组合右侧安全边距内。
状态移至日期范围旁，底部
图例分成疏开的两行并居中。所有文字保持原字号，不靠缩字腾空间。
七个星期仍是一个多行标签，行位置间隔 20px。绘制和像素检查共同使用
`main/reset_ui_layout.h` 中的几何常量，保留背景的长按弹窗仍在原 24 KiB 池内运行。

`00-captured-history.png` 的真实八周捕获含 16 条记录、一个完整分页，响应生成
时间为 2026-10-04T14:55:20.166Z，显示 UTC 范围为 2026-08-10 至 2026-10-04。
它与双色/未知/未来压力测试模拟输入明确区分。

## 检查

字形覆盖检查两种正文字体、极小相对时间字体及已知缺失 U+9F98；每个可见标签
实际字体、行宽、正文行预算、屏幕和父对象边界均受检查。输入覆盖所有顶层页、
配网错误、计划公告旧于最近公告、空/超时计划、仅预测/过期预测、长词/URL、缺字、
字节/页数上限、全部八页正文，以及 API/时区变化期间正文和来源冻结。

历史包括真实捕获、局部覆盖、读取/错误、未来日、未知时钟、全部 56 格同时含
两种类型。独立像素探针检查每格两半颜色与模型一致。首页、二维码和最坏历史页
分别运行 500 个真实长按进度帧及 100 次取消/打开关闭循环，要求对象稳定、预热
后的活动分配数和空闲字节完全一致。二维码另跑 100 次正文/来源切换和 111 次真实二维码对象检查；只显示不可用提示
不能通过检查。正文跑
500 次变化，四个顶层页测量 1200 次切换，没有分配增长容差。

最终默认八周主机运行检查 317614 个标签，缺字/裁剪均为零；582 个首页语义颜色
探针、1672 个历史颜色/留白探针均无失败。内存池峰值为 18288/24576 字节（恢复
基线为 18648）。最坏历史长按保留 23 个对象、223 次活动分配，前后均空闲 4104
字节；取消后 193 次活动分配、空闲 5864 字节。
这些是主机池结果，不代表 ESP32 总堆验收。

独立二维码像素解码需要 Pillow 和 zxing-cpp：

```bash
python3 tests/test_reset_qr_decode.py build/v2.4-history-final/screens
```

六个真实二维码输出（回退、最大 URL、畸形/观察回退、冻结来源及捕获 API 来源）
都需验证精确 URL、不少于 3px 的整像素模块和完整静区。冻结正文的二维码在 API/
时区变化后仍解码为原计划来源。这不能代替真实 LCD 上的手机光学扫码。

输出 PNG/PPM、标明模拟输入的拼图、`audit.txt`、`manifest.json`、
`hold-scenarios.json` 和长按 GIF。即使已有图片，检查失败仍返回非零。
亮度、电量 ADC、物理按键、无线/TLS 内存压力、凭证、LCD 字形和手机扫码仍需
设备测试；主机渲染不是 `Device tests: PASS`。

二维码准入按真实 I1 行跨度×高度、调色板和对齐开销计算构造默认画布与目标画布
共存的峰值，因为 LVGL 先分配新画布再释放旧画布；另计画布描述符、编码器临时
缓冲区及保守对象开销。总空闲覆盖总峰值，最大连续块只针对单次分配，避免旧的
固定 6000 字节门槛在捕获数据/历史导航后误拒。画布创建后的双临时缓冲区安全
检查仍保留。

## 本轮样式回归范围

在只改样式前，先渲染恢复的 v2.4 基线。普通正文、统计、设置、长按进度帧和冻结
来源二维码 PNG 均与基线逐字节相同。变化仅为首页卡片固定语义配色、内部层级及
时间位置，以及日历间距、浅边框和图例布局。展示模型、数据、按键、联网、
熄屏、二维码编码/URL/预算逻辑及字体资源未改变，完整输入序列仍通过既有内存
和独立二维码解码检查。

### 时间容器的光学居中

未来大卡浅蓝时间板、最近一次的大/小黄色时间容器，都按真实字形联合边界居中，
使用 LVGL 行高、基线、字形高度及 y 偏移；剩余奇数像素向上取整，不靠较大的
行框或每条文案猜偏移。实际渲染像素要求上下墨迹余白之差不超过一像素；210 次
检查全部通过，覆盖压缩状态的 99 天 23 小时、9999 天、刚刚、时间待核对和无记录。
新增未来时间内板对象也经过原 500 帧长按/100 次取消循环，活动分配严格稳定。
时间内板细调本身未改历史；之后按要求进行的边距微调仅将整表左移，不改变
格子大小、横纵间距、字号、数据或图例。八次实际可视边界检查要求框内两侧至少
留 7px、差值不超过 1px，全部通过。两种首页状态 PNG 与最终时间内板版本逐字节
相同。
